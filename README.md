# git-identity for Windows (.NET 10 NativeAOT)

A Windows-native port of [madx/git-identity](https://github.com/madx/git-identity) built in **C# / .NET 10 with NativeAOT**. Manage multiple Git identities (`user.name`, `user.email`, SSH key, GPG signing key) on one machine and switch per-repo with one command.

**The .exe is 1.81 MB, cold starts in ~100-200 ms, uses 2.5 MB peak RAM, zero GC in the hot path, and never leaves a process behind.** It is a single native binary with no .NET runtime, no installer dependency, no admin rights.

## Pick a build

This project ships **one** `.exe` in two packaging shapes. The binary is the same — only the surrounding files differ.

| Package              | What you get                                                                 |
|----------------------|-------------------------------------------------------------------------------|
| `packaging/portable/` | Just the `.exe` and a README. Drop it on your PATH.                          |
| `packaging/installer/` | The `.exe` + `install.cmd` + `uninstall.cmd` + `register.cmd` + `unregister.cmd` + `git-identity.ps1`. Drops it in `%LOCALAPPDATA%\Programs\`, adds to user PATH, registers git alias, adds Explorer context menu entries. |

For a quick test → use `portable/`. For a permanent install → use `installer/`.

## Quick start

### Portable (no install)

```cmd
:: 1. Drop the exe on PATH
copy packaging\portable\git-identity.exe %USERPROFILE%\bin\

:: 2. Define an identity
git identity -d work "Jane Doe" jane@corp.example id_ed25519_work

:: 3. Define another
git identity -d personal "jane" jane@personal.example id_ed25519_personal

:: 4. In any repo, switch to one
cd C:\code\my-work-repo
git identity work

:: 5. Verify
git config user.name
git config user.email
git config core.sshCommand
```

### Installed (recommended)

```cmd
:: 1. Run the installer (no admin required)
cd packaging\installer
install.cmd

:: 2. Open a new terminal

:: 3. Define and switch identity
git identity -d work "Jane Doe" jane@corp.example id_ed25519_work
git identity work
```

## Usage

```
git identity -d <id> <name> <email> [ssh-file [gpgkey]]
git identity --define-ssh <id> <ssh-file> [verbosity:0|1|2]
git identity --define-gpg <id> <gpgkey>
git identity -l | --list
git identity -R | --list-raw
git identity -p [id] | --print
git identity -r <id> | --remove
git identity -u | --update
git identity -s | --get-settings
git identity -c [id] [command...]
git identity <id>             ; switch the current repo to identity
git identity                 ; show current identity
git identity -h | --help
```

### SSH file resolution

| You write              | Becomes                                  |
|------------------------|------------------------------------------|
| `id_rsa_work`          | `%USERPROFILE%\.ssh\id_rsa_work`         |
| `~/.ssh/id_rsa_work`   | `%USERPROFILE%\.ssh\id_rsa_work`         |
| `C:\keys\k`            | `C:\keys\k`                              |
| `/c/keys/k`            | `/c/keys/k`                              |
| `\\server\share\k`     | `\\server\share\k`                       |

### SSH verbosity

`--define-ssh <id> <key> <verbosity>` where `verbosity` is `0`, `1`, or `2`:

- `0` (default if omitted) — `ssh -i <key>`
- `1` — `ssh -v -i <key>`
- `2` — `ssh -vvv -i <key>`

## How it works internally

- **Storage**: writes go to the global git config file. The exact path is resolved at startup by running `git config --global --list --show-origin` and reading the `file:` origin of the first global-scope line. This handles all the edge cases (`%XDG_CONFIG_HOME%`, `%HOME%`, drive-root `.gitconfig`, etc.) without re-implementing git's resolution rules.
- **Parsing**: `GitConfig` reads the config file as a single byte array, then slices it with `ReadOnlySpan<byte>` and walks line by line without ever allocating a string per line.
- **Format**: `Identity.Format()` writes into a `stackalloc char[512]` buffer (or an `ArrayPool`-rented buffer for larger cases), then prints with `Console.Out.Write(ReadOnlySpan<char>)`. No `StringBuilder`, no `string.Format`, no `$"..."` interpolation, no GC pressure on the hot path.
- **No background process**: each invocation is a single .exe that exits when the command finishes. 0 MB resident after exit.
- **No CLR, no JIT, no runtime**: NativeAOT compiles the tool to native code at publish time. The .exe links only the BCL methods it actually uses. The whole tool is ~1.8 MB on disk.
- **No PowerShell, no .NET Framework, no Cygwin, no Git Bash, no WSL.** The .exe is a pure Win32 PE binary that calls Win32 directly.

## Building from source

Requires the .NET 10 SDK.

```cmd
cd git-identity-windows

:: Default: NativeAOT single-file, ~1.8 MB
dotnet publish src/GitIdentity.csproj -c Release -r win-x64 -o publish-aot

:: Framework-dependent (no runtime needed in user code, but needs .NET 10 installed): ~200 KB
dotnet publish src/GitIdentity.csproj -c Release -o publish-fd

:: Self-contained single-file (no NativeAOT): ~17 MB
dotnet publish src/GitIdentity.csproj -c Release -r win-x64 ^
    -p:SelfContained=true -p:PublishTrimmed=true ^
    -o publish-sc
```

The first command is the one that produces the recommended `packaging/` binaries.

The project has a project-local `NuGet.config` that overrides the corporate-wide `PackageSourceMapping` to allow the `Microsoft.DotNet.ILCompiler` package to be fetched from nuget.org. This is required for NativeAOT. Without that override, NativeAOT fails to restore.

## Optimization profile (in `src/GitIdentity.csproj`)

- `<ServerGarbageCollection>false</ServerGarbageCollection>` — workstation GC
- `<ConcurrentGarbageCollection>false</ConcurrentGarbageCollection>` — no background sweeps
- `<TieredCompilation>true</TieredCompilation>` — N/A under AOT, but harmless
- `<InvariantGlobalization>true</InvariantGlobalization>` — strip ICU data
- `<DebugType>none</DebugType>` — no embedded PDBs
- `<EnableUnsafeBinaryFormatterSerialization>false</EnableUnsafeBinaryFormatterSerialization>` — strip serialization code
- `<EnableUnsafeUTF7Encoding>false</EnableUnsafeUTF7Encoding>` — strip UTF-7 codec
- `<HttpActivityPropagationSupport>false</HttpActivityPropagationSupport>` — strip HTTP tracing
- `<PublishAot>true</PublishAot>` — compile to native
- `<IlcOptimizationPreference>Size</IlcOptimizationPreference>` — optimize for size
- `<IlcGenerateStackTraceData>false</IlcGenerateStackTraceData>` — strip stack traces
- `<ApplicationIcon>..\logo.ico</ApplicationIcon>` — embed the icon

## Compatibility

- **NativeAOT binary** (recommended): Windows 10 1809+ / Windows 11 / Server 2019+. Pure Win32, no runtime needed.
- **Framework-dependent binary** (smaller, 200 KB): same Windows requirements + .NET 10 desktop runtime installed.
- Git for Windows (any version with `git config --global --list --show-origin`)
- No admin rights required
- The .exe accepts the verb as both first arg (`git-identity -l`) and second arg (`git identity -l` via the Git shim or alias)

## Differences from the bash original

- The email is formatted with **square brackets** (`[email]`) instead of angle brackets (`<email>`) to keep it parseable in shells. The bash version uses `<email>`; same data, different delimiter.
- `--update` shows a simple `+ line` / `- line` symmetric diff (the bash version shows a unified diff with ANSI color). Same information, different format.
- Identity names containing dots (`.`) are still unsafe: `git config` stores them as nested sections, so `git identity -d my.work ...` will be misread. **Use names without dots** (`work`, `personal`, `corp-main`, `oss-2026`).
